결론. 보관한 기사가 며칠 뒤 사라지는 문제(가장 심각)를 포함해 확인된 6건을 모두 고쳤습니다. 자동 시험 21개를 새로 만들었고, 고치기 전에는 14개가 실패했으며 고친 뒤에는 21개 모두 통과합니다. 저장소에 올라간 비밀값은 없습니다.
주인이 정할 것
  1. 이미 들어간 가짜 번역 235문장을 지울지. 지금은 화면에서만 "(이 기사는 한글 번역이 없습니다)"로 가립니다. DB 파일은 그대로입니다. 진짜 번역을 원하면 번역 서비스를 붙여야 하고, 그러면 비용이 생길 수 있습니다.
  2. 스포츠 칸 배분(테니스 4 · MLB 2 · 프리미어리그 2 · 기타 2). 제가 임의로 정한 숫자입니다. 바꾸려면 update_news_cron.py와 index.html의 SPORT_MIN_SLOTS 두 곳을 같이 고치면 됩니다.
  3. 자동 기사 퀴즈의 내용. 보기 순서는 섞었지만 "이 기사의 주제는?"에 기사 제목이 보기로 나오는 구조는 그대로입니다. 쉽게 맞히는 문제라서 제대로 된 문제를 만들려면 문제를 만드는 방식부터 바꿔야 합니다.
  4. 보관 사본은 이 브라우저에만 있습니다. 브라우저 데이터를 지우거나 다른 기기에서 열면 보관함이 비어 있습니다. 기기 사이에 보관함을 맞추려면 서버 저장소가 필요합니다.

시험 방법

  • node --test tests/audit/app.test.mjs (앱 14개): index.html 안의 스크립트를 Node에서 가짜 화면과 함께 실행합니다. 브라우저는 띄우지 않습니다.
  • python -m unittest tests/audit/test_scripts.py (스크립트 7개): 임시 폴더에 복사본을 만들어 돌리고, 뉴스 수집은 가짜 응답으로 바꿔서 인터넷에 접속하지 않습니다.
  • 기존 시험 verify_readpulse.py(Chrome 화면 시험)도 인터넷을 막고 돌렸습니다. 카드 63개 표시, 읽기 화면, 단어 저장, 쉐도잉 안내 문구, 퀴즈까지 모두 통과했습니다. 마지막 "콘솔 오류 0개" 검사만 실패했는데, 제가 인터넷을 막아 글꼴과 사전 API를 못 불러온 오류 3건입니다. 앱 코드 오류는 없었습니다.
  • 기존 시험은 가짜 발음 점수가 나와야 통과하도록 짜여 있어서, 마이크가 없을 때는 안내 문구가 나오는지 보도록 고쳤습니다.
  • 실제 DB(기사 63개)로 모든 기사를 열고 대역 모드로 그려 보는 점검도 오류 없이 끝났습니다.

확인 못 한 것

  • 실제 휴대폰·PC 브라우저에서 눈으로 본 화면 확인은 하지 않았습니다. "(번역 없음)" 문구와 마이크 안내 문구가 어떻게 보이는지 한 번 봐 주세요.
  • 실제 마이크로 말해서 채점되는 경로는 자동 시험(가짜 음성 인식 결과)으로만 확인했습니다.
  • GitHub Actions 자동 갱신은 실행하지 않았습니다. BBC·ESPN 피드에 실제로 접속하는 부분은 시험에서 가짜 응답으로 바꿨습니다.
  • 이미 사라진 보관 기사는 되살리지 못합니다. 이번 수정 뒤에 보관한 기사, 그리고 아직 목록에 남아 있는 보관 기사부터 보호됩니다.
  • DB 파일(articles_database.js)은 고치지 않았습니다. 다음 자동 갱신부터 새 규칙이 적용됩니다.
